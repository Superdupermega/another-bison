Open metric

Spec Sufficiency Score

A spec that scores 90 can be handed to any agent, any vendor, any contractor. A spec that scores 40 will be built wrong four times. SSS turns "is this spec good enough?" into a number you can track, require in a contract, and show a regulator.

How it is computed

Run the spec through N independent autonomous coding agents in clean environments (we use N = 3 across at least two model vendors). Measure four things and combine them.

ComponentMeasureWeightWhy
Q · Question rateClarifying questions raised per agent, normalised: Q = max(0, 1 − questions / 5)35%Every question is a spec defect. Zero questions is the goal.
P · First-pass rateShare of acceptance tests passing on the agent's first submission, averaged across agents35%Sufficiency means the agent knew what "done" was.
V · Behavioural agreementShare of property-test cases where all N implementations agree20%Low agreement means the spec left room for interpretation.
C · Cost stability1 − (coefficient of variation of cost-to-green across agents), clipped to [0,1]10%Wild cost variance means agents wandered.
SSS = 100 × (0.35·Q + 0.35·P + 0.20·V + 0.10·C)

Bands:  ≥ 85  Sufficient — hand to any agent
        65–84 Workable — expect one revision cycle
        40–64 Ambiguous — expect rework and drift
        < 40  Not a spec

Run it yourself with the reference harness: python3 tools/sss/sss.py examples/refund-eligibility.bis.yaml --runner mock. Plug in your own agent with --runner cmd --cmd "...". Formula and harness are open; hosted scoring in CI is on the roadmap.
