Glossary

The vocabulary of intent engineering

Terms we use precisely, so that specs, contracts, and audits mean the same thing to everyone.

Intent engineering
The discipline of translating business needs into specifications precise enough for autonomous agents to implement without clarifying questions and for verification systems to prove.
Bison Intent Spec (BIS)
An open, structured spec format with mandatory sections: outcome, objective function, constraints, edge cases, data contracts, accountability, do-not-build list, acceptance tests, evidence.
Spec Sufficiency Score (SSS)
A 0–100 measure of whether a spec can be implemented by independent agents with no questions, first-pass test success, behavioural agreement, and stable cost.
Spec defect
Any clarifying question an agent raises during implementation. Logged, attributed to a spec section, and fixed upstream.
Objective function
The prioritised list of what the system optimises, each with a metric, a target, and a hard floor.
Hard floor
The value of a metric below which the situation is an incident, not a regression.
Constraint
A rule that must never be violated, with a named enforcement point and a verification reference.
Enforcement point
The specific middleware, router, schema, or transaction boundary that makes violating a constraint impossible or detectable. "The model should never" is a wish until it has one.
Do-not-build list
Explicit non-goals so that agents do not over-deliver.
Topology
The designed structure of a multi-agent system: roles, protocols, delegation paths, consensus rules, fallback loops, cost envelopes.
Fallback loop
A deterministic route taken when an agent halts, drifts, returns malformed output, disagrees, loses its provider, or breaches budget.
Deterministic integration
Wiring non-deterministic model decisions into transactional systems with idempotency, sagas, event contracts, replay, and circuit breakers.
Fence
Bison's policy-enforcing proxy for LLM traffic, at ingress and egress.
Model equivalence
Evidence that a system's properties hold unchanged when the underlying model is swapped.
Evidence table
The record of which test verified which property, when, with what result, signed by the accountable role.
Accountable role
The named human role that owns the risk of a class of automated decision. A role, never a person's name, so accountability survives reorganisation.
Attestation
A formal, repeatable statement that named properties were verified by named tests on a named date. Attests to evidence, not to outcomes.
